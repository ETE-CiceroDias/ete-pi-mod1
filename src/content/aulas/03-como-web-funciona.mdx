## O que é a Web?

A Web — *World Wide Web* — não é a internet. A internet é a infraestrutura física: cabos, roteadores, servidores conectados globalmente. A Web é um serviço que roda **sobre** essa infraestrutura, usando o protocolo HTTP para trocar documentos — páginas, imagens, vídeos, dados.

Quando você digita `google.com` no navegador e pressiona Enter, uma cadeia inteira de eventos acontece em milissegundos. Entender essa cadeia é entender onde o seu código vive.

---

## O que Acontece Quando Você Digita uma URL

```
https://www.google.com/search?q=html
│       │               │     └── query string
│       └── domínio     └── caminho (path)
└── protocolo (HTTPS)
```

### 1. DNS — Traduzindo nome em endereço

O navegador não sabe o que é `google.com`. Ele só entende endereços IP — números como `142.250.185.46`. O **DNS** (*Domain Name System*) é o sistema que faz essa tradução.

Funciona como uma agenda telefônica da internet:
- Você pede: *"qual o IP de google.com?"*
- O DNS responde com o número
- O navegador usa o número para conectar ao servidor

### 2. HTTP e HTTPS — A conversa entre cliente e servidor

**HTTP** (*HyperText Transfer Protocol*) é o protocolo que define como o navegador (cliente) e o servidor conversam.

**HTTPS** é HTTP com criptografia — os dados trafegam embaralhados, protegidos. O `S` vem de *Secure*.

A conversa básica é:
- **Request (pedido):** "Me dê o arquivo `/index.html`"
- **Response (resposta):** "Aqui está, com status 200 (OK)"

### 3. O servidor responde

O servidor recebe o pedido, encontra o arquivo solicitado e envia de volta. Para uma página HTML simples, ele manda o arquivo `.html`. O navegador recebe e começa a trabalhar.

### 4. O navegador renderiza

O navegador lê o HTML de cima para baixo. Quando encontra referências a CSS e JavaScript, faz novos pedidos para buscar esses arquivos. Depois de reunir tudo, **renderiza** — transforma o código em pixels na sua tela.

## Os Três Pilares da Web

| Tecnologia | Responsabilidade | Quando entra em cena |
|---|---|---|
| **HTML** | Estrutura e conteúdo | Primeiro — é a base |
| **CSS** | Aparência visual | Depois do HTML |
| **JavaScript** | Comportamento dinâmico | Por último, ou sob demanda |

<Callout type="tip" title="Você pode ter uma página sem CSS e sem JS">
  Uma página sem CSS fica feia, mas funciona. Uma sem JS fica estática, mas é legível. Mas sem HTML não existe página — HTML é sempre a fundação.
</Callout>

## Conceitos Essenciais

### URL — Uniform Resource Locator

Uma URL é o endereço de um recurso na web. Cada parte tem significado:

| Parte | Exemplo | O que é |
|---|---|---|
| Protocolo | `https://` | Como comunicar |
| Domínio | `developer.mozilla.org` | Qual servidor |
| Caminho | `/pt-BR/docs/Web/HTML` | Qual recurso no servidor |

### Status Codes — O servidor respondendo

Quando o servidor responde, ele inclui um código de status:

| Código | Significado |
|---|---|
| `200 OK` | Tudo certo, aqui está o recurso |
| `404 Not Found` | O recurso não existe nesse caminho |
| `301 Moved Permanently` | O recurso mudou de endereço |
| `500 Internal Server Error` | Algo quebrou no servidor |

<Callout type="info" title="O famoso 404">
  O erro 404 é tão comum que virou cultura pop. Ele aparece quando você tenta acessar uma URL que não existe no servidor — seja porque o endereço está errado, seja porque a página foi removida.
</Callout>

### Cliente e Servidor

**Cliente** é quem faz o pedido — geralmente o navegador. **Servidor** é quem responde — um computador rodando um programa que aguarda conexões e serve arquivos ou dados.

Quando você cria uma página HTML e abre ela direto no navegador (sem HTTP), não há servidor envolvido — o navegador lê o arquivo direto do seu disco. Isso funciona para desenvolvimento, mas não é como a web real funciona.
